## 一、模块职责（改代码前先看这张表）

| 模块 | 行数 | 职责 | 什么时候改它 |
|---|---|---|---|
| `config.py` | ~92 | 活动 id、开火参数默认值、**错误码表**、路径 | 换活动、调默认参数 |
| `device.py` | ~287 | 手机操作：串号自动探测、唤醒、冷启动、前台、保活、息屏、dump | 设备侧行为要变 |
| `webview.py` | ~324 | frida ↔ mecox 桥、**选页加固**、重连 | 注入/选页出问题 |
| `panel.py` | ~129 | 活动接口：场次/地址/校验/兑换/余额 | 接口变了（新参数/新路径） |
| `slots.py` | ~165 | 场次与商品解析（**选目标的全部逻辑**） | 选场规则要变 |
| `sniper.py` | ~147 | 狙击手安装/武装/状态/结果摘要 | 武装参数、结果解析 |
| `sniper.js` | ~429 | **页面内狙击手**（对时→找场→自旋→串行链开火） | 开火逻辑要变 |
| `grabber.py` | ~324 | 一次抢兑的编排 + 日志 | 流程要加步骤 |
| `monitor.py` | ~88 | 设备状态采样监控 | 监控项要加 |
| `guard.sh` | ~73 | 设备端守护（冷启动+守前台+息屏） | 设备端时序要变 |
| `cli.py` | ~245 | 命令行入口 | 加子命令 |

**数据流**：

```
cli.py
  └─ grabber.run()
       ├─ device.cold_start_pdd()          冷启动刷新会话
       ├─ webview.Bridge.connect()         frida 连上
       ├─ webview.Bridge.ensure_page()     确认活动页可见
       ├─ panel.query_time_awards()        读场次表
       ├─ slots.pick_slot()                选目标场次+商品
       ├─ panel.default_address()          读地址
       ├─ sniper.install() / arm()         装+武装（sniper.js 注入页面）
       └─ sniper.status() 轮询             读结果 → 摘要
```

## 二、命令行

```bash
cd G:\vp\pdd-grab\api

python -m pddgrab.cli status                   # 一行看设备状态（1 秒，最快）
python -m pddgrab.cli env                      # 配置 + 设备状态
python -m pddgrab.cli list --item 汰渍          # 列场次商品（目标带标记）
python -m pddgrab.cli probe --item 汰渍         # 只读自检
python -m pddgrab.cli fire --item 汰渍          # 完整跑一次
python -m pddgrab.cli arm --item 汰渍           # 只武装（不盯）
python -m pddgrab.cli coupon --yes             # 兑 1 卡券（花 1 张卡，验链路）
python -m pddgrab.cli monitor --until 22:05    # 设备状态监控
python -m pddgrab.cli guard --wake 21:55 --sleep 22:05   # 设备端守护
python -m pddgrab.cli stop-guard               # 停守护
```

**常用参数**：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--item` | — | 商品关键词（`goods_name` 包含它就算命中） |
| `--award-id` | — | 直接指定奖品 id（优先级高于 `--item`） |
| `--at HH:MM` | 自动 | 开火时刻；默认取「未开始的最近一场」 |
| `--attempts` | 120 | 最多打几发 |
| `--gap` | **0** | 两发间隔 ms。**0 = 串行链（推荐）**；不要填 1~799 |
| `--from-ms` | -1000 | 首发相对场次开始的偏移（负数=提前） |
| `--no-cold-start` | 关 | 跳过冷启动（**不推荐**，会得 `250013`） |

## 三、当库用

```python
from pddgrab import grabber, slots, panel, device
from pddgrab.webview import Bridge

# 1) 完整跑一次
res = grabber.run(item="汰渍")
print(res.summary())
if res.ok:
    print("抢到了，余额", res.balance_after)

# 2) 只读自检
info = grabber.probe(item="可口可乐")
print(info["target"], info["address"])

# 3) 只武装，让页面自己到点开火（PC 可以断开）
r = grabber.arm_only(item="汰渍", at="22:00")

# 4) 细粒度操作
device.cold_start_pdd()
with Bridge() as b:
    t = b.ensure_page()
    res = panel.query_time_awards(b, t)
    print(slots.describe(res, keyword="汰渍"))
    pick = slots.pick_slot(res, keyword="汰渍")
    print(pick["name"], pick["award_id"], pick["consume"])
    addr = panel.default_address(b, t)
    code, raw = panel.exchange(b, t, pick["award_id"], addr)   # ⚠️ 会真兑换
```

## 四、常见改动怎么做

### 换商品

```bash
python -m pddgrab.cli fire --item 天堂晴雨伞
python -m pddgrab.cli fire --award-id 1402419
```

不用改代码。`slots.find_item()` 支持「关键词」和「award_id」两种匹配。

### 换活动（另一个页面 id）

```bash
export PDD_ACT_ID=195846        # 活动页 id
export PDD_URL_HINT=attendance  # URL 识别子串
```

或改 `config.ACT_ID`。

### 换设备 / 换串号

串号**自动探测**（环境变量 → 无线地址 → USB → adb 已连上的任意设备）。

```bash
export PDD_ADB_SERIAL=192.168.1.50:5555      # 你的手机（USB 串号或 ip:5555）
export PDD_WIFI_ADDR=192.168.1.50:5555      # 无线 adb 地址（会自动 connect）
```

### 调开火参数（不改代码）

```bash
export PDD_ATTEMPTS=150
export PDD_GAP_MS=0
export PDD_FROM_MS=-1500
```

### 加一个新的错误码说明

改 `config.ERR`，`err_text()` 会自动翻译。

### 加一个新的监控项

改 `monitor.Monitor.run()` 里的采样行。

## 六、日志在哪

| 位置 | 内容 |
|---|---|
| `api/logs/fire_*.log` | 每次 `fire` 的完整日志（每发 drift/rtt/错误码、余额变化） |
| `api/logs/monitor_*.log` | 设备视角（屏幕/PDD 进程/前台），窗口内 10 秒一采样 |
| `api/shots/*.png` | 截图存证 |
| 手机 `/data/local/tmp/pdd_guard.log` | guard 的冷启动/息屏时间线 |

**复盘方法**：把 `fire` 日志（请求视角）和 `monitor` 日志（设备视角）
按时间对齐，就能定位「那一刻到底谁在挡路」。

## 八、性能约定（别把等待写进流程）

抢兑只有一次机会，等待时间要花在刀刃上。代码里的约定：

| 做法 | 为什么 |
|---|---|
| `device.status()` **一次 adb 调用**取全部状态 | 原来拆 4~5 次 shell 来回，慢 5 倍 |
| `panel._xhr()` 轮询间隔 **0.2s** | 响应通常 200ms 内就回来，没必要等 0.4s |
| `ensure_page()` 重试间隔 **5s**（原来 10s） | 页面就绪一般 5 秒内 |
| 需要息屏时用 `sleep_screen_now()` | **别等 60 秒超时**，直接 `input keyevent KEYCODE_POWER` |
| 需要等某个时刻 → 交给**设备端 guard** | PC 前台干等是最浪费的 |
| 不做冗余校验 | 工具返回成功就是成功，只在「结果决定下一步」时才验证 |
